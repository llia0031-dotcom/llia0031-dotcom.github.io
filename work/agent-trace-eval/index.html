一分钟看完

会调工具的 Agent 只看最后答案对不对不够：它每一步做了什么，上线前的检查能拦住哪些错，失败从哪一步开始，改了以后会不会把别处弄坏。

我给三个已有的、会调工具的 Agent 新写了 46 道题，每题跑三次，把每一步记下来；评分按理解、规划、工具调用、知识引用、结果五个阶段写成规则，再加上线前的自动关卡和失败归因表。看完基线后，跑之前先写下两个修复的预测，再在整组题上做回归重测。

上线前的自动关卡查的是形式：引文是不是原话、数字有没有出处、时长对不对；它们放过的，正是判断上的错。会调工具的 Agent 要按步骤评，才能看清失败从哪里开始、哪些是题目本身的问题。照失败写的修复要先写下预测，再在整组题上回归重测，否则修好一处、弄坏另一处也看不出来。

局限

01每题​只​跑​三次，​题目​是​为​这​套​评测​新​写的，​区间​很​宽

经营分析任务成功 47/54（87.0%，95% 区间 75.6 至 93.6%）；按题比较只靠三次试验。建议：重要的结论多跑几次、加新题再确认。

02题目​是​合成​或​虚构的，​出自​运行​它的​同​一个​项目

有两道题的题目或答案本身有问题，照实留在分数里。建议：给那两道题改名或重建后重跑，并用真实业务里已有结论的样本另建一组题。

03判官​和​被​测的 ​Agent ​是​同​一个​模型，​指南​在​平静的​周​上有​漏洞

判断项不影响任务成功，也没有另做人工评分。建议：补上指南的漏洞，换一个不同的模型做第二判官对照。

04两​个​修复​只在​写​它们的​那​组​题​上​验证​过

时延只来自基线第一次走普通接口的试验，每题一次。建议：用新题检验修复能不能推广，再把规则搬进代码后重测退款类的题。
