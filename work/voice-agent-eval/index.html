一分钟看完

语音助手在用户停顿、插话、说“嗯”、背景有人说话时还能不能把事办对，体验用时延、打断、误停的数字来衡量（用户语音是合成的）。

我写了 42 段带停顿、插话、附和和噪声的对话、事先定好答案，搭了一条本机串联的语音 Agent 做基线；然后一项一项试改进，每项先写补充跑评测之前，先把题目、规则和算分办法写下来并冻结，跑完不能改。再跑，最后把有效的合在一起。

四项改进合在一起，在这几项改动针对的问题上是测过最好的设置：背景人声不再占住对话、真插话一停就停、每次附和后回答都保住了；按事先写好的严格通过和基线持平。“嗯嗯”仍被识别成别的字，合在一起时只因为发声时间刚好不到 0.5 秒才没打断，余量很小，光看文字分不出附和。

动手前以为的

以为固定识别语言，就能把“嗯”和真插话分开

评测数据说明的

“嗯嗯”仍被认成别的字，四项合在一起时只因发声不到半秒才没打断

  • 4.56 秒 背景有人说话时，开口要等（原来 20.4 秒） 中位数，n=8，95% 区间 2.97 至 5.69
  • 0.25 秒 用户插话后，助手多快停下来 中位数，n=16，95% 区间 0.25 至 0.28
  • 16/16 用户真的插话时，助手每次都停下 100.0%，95% 区间 80.6 至 100.0%

评测

主评测：三种基线设置和纯文字对照（42 段对话）

42 段对话，每种设置 2 遍，共 84 段；claude-haiku-5-5，普通流式接口

  • 静音检测基线（开思考）：严格通过 61/84
  • 纯文字对照：严格通过 82/84
  • 开思考：背景人声题说完到开口 20.4 秒 20.4 秒（中位数，n=8，95% 区间 19.1 至 22.5）
  • 开思考：用户只说“嗯”“好的”时继续说 0/8

逐项改进（同一套 42 段对话）

42 段对话，每种设置 2 遍；claude-haiku-5-5，普通流式接口

  • 四项合在一起：严格通过 62/84
  • 只听主说话人：背景人声题说完到开口 4.56 秒 4.56 秒（中位数，n=8，95% 区间 2.97 至 5.69）
  • 四项合在一起：真插话时停下 16/16
  • 四项合在一起：插话到停下 0.25 秒 0.25 秒（中位数，n=16，95% 区间 0.25 至 0.28）
  • 附和不算打断：用户只说“嗯”“好的”时继续说 4/8
  • 再固定识别语言：用户只说“嗯”“好的”时继续说 4/8

点是结果，条是 95% 区间，横轴 0 到 100%带箭头的数字能点开出处

局限

01用户​语音​是​合成的，​时间​是​模拟的

42 段对话每种设置只跑两遍，相差一两段属于噪声。建议：上线前用真人录音（例如公开的对话语音数据）重跑，并在真实网络下测时延。

02“嗯嗯”​这类​附和​仍​被​识别器​听成​别的​字

单项改进时它会打断，四项合在一起时只因为发声时间刚好不到 0.5 秒才没打断，余量很小；光看识别出的文字分不出附和和短插话。建议：用看声音本身的附和检测；现成的声学附和模型离线试过，没达到事先定的标准，所以没接进来。

03没有​和​端到端​实时​语音​模型​比较

建议：接上一个有免费额度的端到端模型，用同一套题和同一个打分脚本比较。
