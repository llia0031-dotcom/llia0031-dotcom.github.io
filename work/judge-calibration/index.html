一分钟看完

用模型当裁判打分省事，可它能信到什么程度；哪些检查可以交给它，哪些该用脚本，哪些必须留给人。

我把一个模型裁判分别和三种标准比：出题时定好的答案、监管和法院的结论、公开数据集自带的人工评分；再定出哪些检查交给脚本、哪些交给裁判、哪些留给人，并做了一个带验收标准的质检 Agent。方案、冻结的文件和预测跑前写好。

模型裁判在答案清楚、能对回原文的检查上可以放心用，能用规则查的交给脚本更稳；要靠外部证据的结论和主观质量评分，裁判和人差得多，应该留给人。裁判自己说“拿不准”的那部分错得多，正好可以拿来决定送人工。

动手前以为的

以为在答案里加“保证没错”这类话会骗过裁判

评测数据说明的

加废话 0/368、加保证语 2/368，没有让错的被放过

  • 702/711 和出题时定好的答案一致 98.7%，95% 区间 97.6 至 99.3%
  • 6/11 要靠外部证据的监管结论，判对 54.5%，95% 区间 28.0 至 78.7%
  • 2/390 规则加裁判加复核漏掉（只用裁判 7/390） 0.5%，95% 区间 0.1 至 1.9%

公开数据集自带的人工评分

规则、裁判和复核队列怎么分工（711 道）

711 道，其中 390 道含错误；每种接法 1 遍；claude-haiku-5-5，effort medium，批量接口

  • 规则、裁判、复核队列：漏掉的错误 2/390

加废话、加保证语会不会骗过裁判（368 道）

368 道；每种改法 1 遍；claude-haiku-5-5，effort medium，批量接口

  • 加废话后判断变了 0/368
  • 加保证语后判断变了 2/368

质检 Agent 和验收标准

239 条记录；模拟批次；每条 1 遍；claude-haiku-5-5，effort medium，批量接口

  • 质检 Agent：错误记录查出 119/119
  • 质检 Agent：正确记录被误报 7/120
  • 错误率百分之二的批次被放行（目标是至少九成） 86.6%
  • 错误率百分之十的批次被放行（目标是不超过一成） 9.4%

点是结果，条是 95% 区间，横轴 0 到 100%带箭头的数字能点开出处

局限

01判断​题​来自​同一​组​项目的​存档​答案，​错误​是​植入的

“论证成错误结论”这类错误样本由 `eval/gen_flips.py` 生成，生成时用的是同一个模型，裁判认得自己写法的偏差没有排除。建议：上线前用真实业务里已经有结论的记录再校准一次，错误样本换不同来源。

02监管​和​法院的​结论​只有 ​46 ​条，​要​靠​外部​证据的​只有 ​11 ​条

区间很宽。建议：这类结论直接留给人，或者先补齐外部证据再交裁判。

03验收​标准​在​错误​率​百分​之二的​批次​上​只​放行了 ​86.6%，​没​达到​事先​定的​至少​九成

百分之十的批次放行 9.4%，达标。质检 Agent 的误报让标记率变模糊，事后看，单靠调标记率门槛两个目标同时达不到。建议：只把复核确认过的标记算进放行门槛（还没测过），再在模拟批次上重测。
