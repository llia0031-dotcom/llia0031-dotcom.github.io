一分钟看完

标注 Agent 怎么设计标得最好，错在哪些标签、哪类样本上，为什么错，改了以后在新样本上还成不成立。

我做了一个通用的内容标注 Agent：换一个放规则和案例的文件夹就能接新任务。用两个任务、五种做法做预注册的 A/B 对照，算每个标签的精确率和召回率、混淆和切片；把最好的做法的失败样本归到五类根因，按根因改出第二版，再在没用过的测试集上检验。常用的分析做成了五个 Agent Skill。

让 Agent 先读规则、再看相似案例，是标注质量最大的来源；自查只在标签多、边界细的任务上值得多花的钱。一个任务能标到多准，先受标准标签本身的限制：点评数据里不少“错误”是可两读或漏标的标签，这部分应该交给定标准的人，而不是继续调提示词。按根因改版要在没用过的样本上再验一次，没测出提升的就不上。

04/ 04

局限

01每​种​做法​每条​只​跑了​一次

模型采样带来的波动不在按题目重抽样的区间里，几处差别离边界很近（点评上查规则对整本规则、一半一半案例库、广告的第二版）。建议：上线前对离边界近的几组多跑几次，确认结论不变。

02广告的​题目​和​广告​规则​出自​同一​组​项目​（有​据​审核、​审核​模型​实验），​答案​在​写​广告​时​定​好，​不是​独立​标​注​员​定的

完整 Agent 在广告上已接近满分。建议：接真实业务前，用业务里已有结论的样本另建测试集。

03点​评的​标准​标签​漏掉了​一些​提及

测试集 A 的 201 条点评里，有 7 条含有在训练集里几乎总伴随某个标签的词，却没有那个标签；根因里还有 158 个判断归为标签歧义。点评上的精确率受这个限制，Agent 的一部分“错误”可能是数据集该有的标签。建议：把可两读或漏标的样本整理给定标准的一方，先统一标注口径，再比较做法。

04合成​点​评比​真实​点​评​短，​而且​是​照 ​Agent ​读的​同一​本​规则​生成的

换一种生成方式，真实对合成的结论可能不同。建议：用不同的生成提示或模型再造一个案例库，重做这组对照。
