运营层

一分钟看完

能核对的回答，怎么变成团队每天用的审核工作流：拿不准的交给人复核，提示词能新版本先只给一小部分请求用，指标没问题再逐步放大。、能新版本出问题时，退回上一个版本。。

我把有据审核做成一条四步审核工作流：模型判断，evidence-check 核对引文，核对没过或模型拿不准的进人工复核队列，复核结果回流成每次改动后都重跑的一组固定题目，确认原来做对的没有变错。；另加政策库检索评测、只按政策库回答的知识库问答、提示词版本、灰度和回滚规则、用 SQL 取数的每周报告和上线检查清单，并在 Lark 多维表格里搭了判断和复核两条工作流。

让模型说“拿不准”能减少判错又生效，代价是多送人工；第一轮灰度按规则回滚，暴露的是规则本身写错；改好的规则在新流量上放到全量，v2 转为正式版本。v2 少漏错判的证据仍来自第一轮。第 3 版在清楚广告上少了多余复核，却把要人来定的广告也少送了人工；第 4 版两头都好了，判错时却更常说“确定”。两版都按事先写好的标准没采用；假如照样放量，灰度规则都拦不下，拦下它们的是题目设计和采用标准。

动手前以为的

以为四条采用标准都满足，灰度就能顺利放量

评测数据说明的

第一轮放到 10% 就回滚：毛病在规则本身；改好后在新流量上放到了全量

  • 9/332 判错又自动生效的（v1 是 17/332） 2.7%，95% 区间 1.4 至 5.1%
  • 10% 第一轮按事先写好的规则，放到这里就回滚了
  • 100% 第二轮在新写的广告上灰度，放到了全量

局限

01流量​是​评测​题的​回放，​不是​真实​用户

复核结论用的是题目定好的答案，没有真的审核员。建议：上线后按版本统计真实请求的漏网错判和复核量，抽检结果回流成回归题。

02v2 ​少​放​过​判错，​但​送​人工​从 ​6​/​332 ​涨​到 ​72​/​332，​很多​是​清楚的​广告​也​说​“拿​不准”

建议：第 3 版放宽“拿不准”，要人来定的也少送了；第 4 版两头都好了，判错时却更常说“确定”。下一版要同时守住三头：清楚的少送、要人定的不少送、判错的不放过，同样先过回归和新题再灰度。

03第二​轮​在​新​流量​上​放到​全量，​但​两​版​在​这​批​广告​上​都​接近​全​对，​没有​再​证明 ​v2 ​能​少​漏​错判

v2 的好处仍来自第一轮。建议：再找 v1 会漏判的新广告（例如更长、更含糊的），在同样的规则下比一次。

04Lark ​里的​平台​模型​一次​也没​说​拿​不准​（0​/​25），​分流​模型的​存档​答案​里​却​有 ​13​/​50 ​说了

机器人问答只有测试，没有真实使用量。建议：换模型后先重新量复核率，再调“拿不准”的门槛；机器人先用一批问题测，再看真实的使用记录。

05中文​问题的​检索​偏​弱

算对的条款进前 5 只有 23/28，库里有答案却说“没有”的都出在检索没找到。建议：中文检索也试本机向量或混合检索，先在选方法时没用过的问题上验。
