Grounded Business ReviewWeekly review: find the cause, trace every number

On synthetic local-services group-buying data, “weekly monitor → breakdown by dimension → weekly review → number check” runs as one repeatable line, and three ways of finding the cause are compared: a fixed-rule script, a one-prompt approach that hands the model a fixed pack of query results, and an agent that queries with tools.

Scenario: judgement

In one minute

Whoever reads the weekly numbers needs to know which metrics moved and why; when a model finds the cause and writes the review, is the cause right, and does every number trace back to a query result? (tested on synthetic data).

On synthetic local-services group-buying data I built a metric dictionary, a one-query weekly monitor, contribution and rate-mix breakdowns and number-checked weekly reviews, and compared three ways of finding the cause: a fixed-rule script, a one-prompt approach and an agent; the known-answer test cases and the evaluation plan were frozen before the run; the same flow was also built as a Dify workflow.

Letting the model decide what to query finds causes best, most clearly when a cause crosses two dimensions; the price is first drafts that cite the wrong row more often and about 1.8× the one prompt’s cost. The fixed script does well on single causes, and these cases cannot separate it from the agent. The number check stopped every number quoted from the wrong row, but it is too strict on Chinese number words and also held back reviews with no wrong number.

What I assumed

Expected most one-prompt first drafts to pass the number check

What the data showed

First drafts passed only 19/36; reviews held back in the end failed on Chinese number words, never on a wrong number

  • 34/36 Agent named every planted cause (one prompt: 28/36) 94.4%, 95% CI 81.9 to 98.5%
  • 0/6 Two-dimension causes the one prompt got right 0.0%, 95% CI 0.0 to 39.0%
  • 19 Agent first-draft paragraphs citing a number not in the row

Limits

01The data, the planted events, the monitor and all three approaches come from the same project

the events are clean and sit inside existing dimensions, which real causes often do not. Recommendation: Before real data, build cases from past weeks whose causes are already known and test again.

02The agent and the script differ by a few cases (p = 0.45)

these cases cannot separate them. Recommendation: Separating them needs more cases, especially two-cause and two-dimension ones.

03The number check is too strict on Chinese number words

the reviews held back in the end had no wrong number, and their failing paragraphs failed on words like 这两项 (“these two”) or 前一天 (“the day before”). Recommendation: Treat counting words apart from quantities, or give them their own rule; how strict to be is a product decision to make with the people who use it.

04The agent’s first drafts had 19 paragraphs quoting a number not in the cited row, all fixed only by the one revision

without the check they would have gone out. Recommendation: Keep the check before anything goes out.

05Recommended actions are not scored

Recommendation: Write scoring rules for the actions and test them on the same cases.
