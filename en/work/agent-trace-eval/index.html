01/ 05

In one minute

Grading only the final answer of a tool-using agent is not enough: what did each step do, which errors do release checks stop, where does a failure start, and does a fix break something else?

I wrote 46 new tasks for three existing tool-using agents, ran each three times and recorded every step; scoring is written as rules over five stages (understanding, planning, tool calls, knowledge and citation, result), with release gates and a failure attribution table on top. After the base run, two fixes were registered with predictions before they ran, then re-tested on every task of their family.

Release gates check form: quotes are the item’s own words, numbers have a source, timings fit; what they let through is errors of judgement. A tool-using agent needs scoring by step to see where a failure starts and which failures belong to the task itself. A fix written from a failure needs predictions first and a regression run over the whole family; otherwise one fix breaking something else goes unseen.

05/ 05

Limits

01Three trials per task over tasks written for this bench, so intervals are wide: business review task success 47/54 (87.0%, 95% CI 75.6 to 93.6%)

per-task comparisons rest on three trials each. Recommendation: Confirm the important findings with more trials and new tasks.

02The tasks are synthetic or fictional and come from the same project that runs them

two have a problem in the task or the key, kept in the scores. Recommendation: Fix and re-run those two tasks, and build another set from real work with settled outcomes.

03The judge is the model under evaluation, and its guide has a gap on quiet weeks

judged items do not affect task success, and no human ratings were collected. Recommendation: Close the gap in the guide and add a second judge from a different model.

04The fixes were checked only on the tasks they were written for

latency comes from the base standard-API trials only, one per task. Recommendation: Test the fixes on new tasks, and re-test the refund tasks after the rules move into code.
