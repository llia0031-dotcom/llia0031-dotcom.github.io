In one minute

How should a labelling agent be built to label best, where and why does it fail, and does a fix still hold on new items?

I built one content-labelling agent that takes on a new task through a folder of rules and cases. Two tasks and five arms go through preregistered A/B comparisons, with per-label precision and recall, confusion and slices; the best arm’s failures are sorted into five root causes, a second version is built from them and checked on a test set nothing was tuned on. The common analyses are packaged as five Agent Skills.

Reading the rules first and then similar cases is where most of the labelling quality comes from; a self-check is worth its cost only on tasks with many fine-grained labels. How well a task can be labelled is bounded first by its gold labels: many “errors” on the review data are labels that read either way or were left out, which belongs with whoever sets the standard, not with more prompt tuning. A revision built from root causes needs a check on unseen items, and one with no measured gain does not ship.

What I assumed

Expected real cases to beat synthetic ones, since they carry the dataset’s labelling conventions

What the data showed

No measured difference between real and synthetic cases: +0.010 [-0.001, +0.022]

  • 0.971 Ads, full agent micro F1 (short prompt 0.768)
  • 0.824 Reviews, full agent micro F1 (short prompt 0.715)
  • +0.018 Revision gain on unseen reviews, adopted 95% CI [+0.005, +0.031]

04/ 04

Limits

01Each arm labelled each item once

sampling variance is not in the item-bootstrap intervals, and several differences sit close to the edge (rules versus the whole rulebook on reviews, the half-and-half library, the ads revision). Recommendation: Before relying on the close calls, run them several more times and confirm they hold.

02The ad items come from the same projects as the ad rulebook (Grounded Review and Policy Model Lab), with answers fixed by construction rather than by independent annotators

the full agent is near the ceiling on ads. Recommendation: Before real use, build a test set from business items with settled outcomes.

03The review gold labels leave out some mentions

7 of the 201 test A reviews contain a phrase that almost always comes with a label in the training split, yet lack that label; 158 decisions were classed as label ambiguity. Precision on reviews is bounded by this, and some of the agent’s “errors” may be labels the dataset arguably should have. Recommendation: Hand the ambiguous or unlabelled cases to whoever sets the standard, settle the labelling rules first, then compare arms.

04The synthetic reviews are shorter than real ones and were generated from the same rulebook the agent reads

a different generator could change the real-versus-synthetic result. Recommendation: Build another library with a different generator or prompt and repeat the comparison.
